Caso de UsoUC01: Realizar Login (RF033 / RNF005 / RNF006)
Ator PrincipalEmpreendedor
Pré-condiçõesUsuário cadastrado no banco de dados; aplicação web em execução.
Fluxo Principal1. O Empreendedor acessa a tela de autenticação (/login).
2. Insere o E-mail / Nome de Usuário e a Senha de Acesso.
3. Clica no botão "INICIAR SESSÃO".
4. O sistema valida as credenciais contra o banco de dados MariaDB/MariaDB utilizando conferência de hash criptográfico via BCrypt.Verify().
5. Confirmada a autenticidade, o sistema gera o cookie de autenticação seguro (CookieAuthenticationDefaults) contendo as Claims de identidade do usuário (UsuarioId, Nome, Email).
6. O sistema redireciona o Empreendedor autenticado para o Painel Geral (/dashboard).
Regras de NegócioRF033 / RNF005 / RNF006: Acesso restrito protegido por autenticação baseada em Cookies seguros com Claims. Senhas armazenadas exclusivamente em formato de hash criptográfico BCrypt. Se as credenciais forem inválidas, o acesso é sumariamente negado e um alerta visual de erro é retornado na tela de login.
Pós-condiçõesSessão autenticada ativa no navegador e isolamento dos dados do usuário carregado no contexto do sistema (Multi-Tenancy).

Regras de NegócioO nome de usuário não pode ser vazio, deve possuir ao menos 3 caracteres e ser único no sistema.
Pós-condiçõesNome de usuário atualizado e sessão reiniciada para atualizar a identidade nas requisições.

Caso de UsoUC03: Alterar Senha de Acesso (RF033 / RNF006)
Ator PrincipalEmpreendedor
Pré-condiçõesO Empreendedor deve estar autenticado e acessar a página de Configurações (/configuracoes).
Fluxo Principal1. O Empreendedor acessa a seção "Alterar Senha de Acesso" em /configuracoes.
2. Informa a "Senha Atual", a "Nova Senha" e a "Confirmar Nova Senha".
3. Clica no botão "ATUALIZAR SENHA".
4. O sistema verifica se a nova senha possui ao menos 4 caracteres e se coincide rigorosamente com a confirmação.
5. O sistema verifica se a senha atual fornecida confere com o hash salvo no banco via BCrypt.Verify().
6. O sistema gera a nova criptografia com BCrypt.HashPassword() e persiste a alteração no banco de dados.
7. O sistema limpa os campos do formulário e exibe notificação visual de sucesso.
Regras de NegócioRNF006: A senha atual deve ser estritamente validada antes de permitir a alteração. A nova senha deve ter no mínimo 4 caracteres e coincidir com a confirmação. O hash gerado é irreversível.
Pós-condiçõesNova credencial de acesso gravada com segurança criptográfica no banco de dados.

Ator PrincipalEmpreendedor (Visitante)

7. O sistema exibe notificação de sucesso e redireciona o usuário para a tela de login (/login).
Regras de NegócioRF034 / RNF005 / RNF006: O e-mail deve ser único e ter formato válido. As senhas são criptografadas com BCrypt. Cada usuário cadastrado possui isolamento de dados estrito por UsuarioId.
Pós-condiçõesConta de usuário criada com sucesso e habilitada para login imediato.

Pré-condiçõesEmpreendedor autenticado e na tela de Materiais (/material).

Caso de UsoUC19: Gerar Novo Orçamento com Custos Detalhados (RF007 a RF014)
Ator PrincipalEmpreendedor, Software Fatiador (Ferramenta Externa)
Pré-condiçõesExistir ao menos um Cliente, uma Peça, uma Máquina e um Material cadastrados. Modelo fatiado previamente.
Fluxo Principal1. O Software Fatiador externo gera a estimativa técnica de peso em gramas e tempo de impressão (HH:MM).
2. O Empreendedor acessa /orcamento/novo.
3. Seleciona o Cliente Solicitante, a Peça (modelo 3D), a Máquina de Impressão e a Matéria-Prima desejada.
4. Insere o Nome do Projeto, o Peso Estimado (g), o Tempo de Impressão (HH:MM) e a Taxa Horária de Impressão (R$).
5. Opcionalmente, clica em "+ ADICIONAR INSUMO DE ACABAMENTO" para selecionar um ou múltiplos insumos (primer, tintas, verniz, solvente) informando a quantidade consumida em mL para cada um.
6. Opcionalmente, informa o Tempo de Acabamento (HH:MM) e a Taxa Horária de Acabamento (R$).
7. Informa a Margem de Lucro desejada sobre a mão de obra.
8. O sistema processa o cálculo de precificação 3D em tempo real:
- Custo Material = Peso (g) * PrecoPorGrama (RN001)
- Custo Acabamento = Somatória de (Consumo_mL * CustoPorMl) + (Tempo Acabamento * Taxa Horária Acabamento) (RN002)
- Custo Energia = (Potência da Máquina (W) / 1000) * Tempo (h) * Tarifa kWh (RN003)
- Custo Total Produção = Custo Material + Custo Acabamento + Custo Energia
- Preço de Venda Sugerido = Custo Total Produção + Mão de Obra + Margem de Lucro
- Margem de Lucro Real = (Lucro Líquido / Preço de Venda) * 100%
9. O Empreendedor clica em "SALVAR ORÇAMENTO".
10. O sistema valida as seleções, grava o orçamento com status inicial "Pendente" (RF013) atrelado ao tenant e redireciona para a Linha de Produção (/producao).
Regras de NegócioRN001, RN002, RN003: Composição completa de custos cruzando material, insumos de acabamento em mL, mão de obra de acabamento em HH:MM e energia elétrica. O orçamento é salvo com status "Pendente". Nenhuma baixa de estoque de filamento ou acabamento é efetuada na criação do orçamento (RN004).
Pós-condiçõesOrçamento criado, precificado analiticamente e registrado na Fila Operacional.

Caso de UsoUC20: Bloquear Criação de Orçamento com Saldo Insuficiente (RF011)
Ator PrincipalSistema LucroImpresso
Pré-condiçõesEmpreendedor preenchendo os dados de peso ou acabamentos na elaboração ou edição de orçamento (UC19).
Fluxo Principal1. O sistema monitora a quantidade de peso em gramas e os volumes em mL dos insumos de acabamento inseridos pelo Empreendedor.

Regras de NegócioRF011: Bloqueio estrito de ordens e propostas de orçamento quando não houver disponibilidade física suficiente de materiais ou insumos em estoque.
Pós-condiçõesIntegridade do estoque preservada e operação inconsistente prevenida com sucesso.

Caso de UsoUC28: Varrer e Excluir Orçamentos Antigos (> 180 dias) (RF019 / RF020 / RN006 / RN007)
Ator PrincipalSistema (Timer / Background Service)
Pré-condiçõesO serviço em segundo plano DatabaseCleanupService (BackgroundService nativo do .NET) em execução no servidor.
Fluxo Principal1. O serviço de background executa periodicamente através de um temporizador regular (PeriodicTimer).
2. O sistema inicializa um escopo de injeção de dependência (IServiceScopeFactory) para acessar os repositórios necessários.
3. O repositório identifica no MariaDB os orçamentos cuja data de criação seja superior a 180 dias (6 meses).
4. O sistema preserva o faturamento acumulado consolidando os valores totais de receitas, custos de material, acabamento, energia e lucro na tabela de Histórico Financeiro antes da purga dos registros físicos (RN007).
5. O sistema remove em lote os registros antigos e consolida as alterações no banco com SaveChangesAsync().
6. O serviço registra log de êxito e permanece em espera para o ciclo seguinte.
Regras de NegócioRN006: Ciclo de vida de dados com expurgo automático de orçamentos inativos há mais de 180 dias (qualquer status). RN007: Preservação de Histórico (Cofre Acumulador) para garantir que o faturamento de vendas antigas não se perca após a limpeza.
Pós-condiçõesBanco de dados otimizado, registros inativos removidos e integridade perpétua do histórico financeiro mantida.
