1. Introdução e Visão Geral

O Diagrama de Máquina de Estados (UML 2.5) modela formalmente os estados discretos, transições válidas, condições de guarda e efeitos colaterais dos objetos nucleares do LucroImpresso. O ciclo principal governa a entidade Orçamento (`Orcamento`) em estreita integração com as regras de negócio de precificação, controle de estoque (RN004), confirmações explícitas de segurança (RN005), ciclo de vida com expurgo em 180 dias (RN006) e cofre acumulador perpétuo (RN007).

2. Máquina de Estados Principal: Ciclo de Vida do Orçamento e Produção

[ST01] EmElaboração (Transient) Status Inicial em Memória
entry / Carregar catálogo de insumos (Clientes, Peças, Máquinas, Materiais e Acabamentos)
do / Calcular custos científicos em tempo real: Material (g), Insumos Químicos (mL), Energia Elétrica (Watts/kWh) e Mão de Obra
exit / Validar saldo de estoque e integridade dos limites via OrcamentoValidator
Transição / SalvarOrcamento() [Saldo Suficiente & Dados Válidos] → Status = Pendente (Persistido no MariaDB) ou EmImpressão quando o status inicial escolhido é Imprimindo
[ST02] Pendente (Persisted) RF013 / RN008
entry / Orçamento salvo na base de dados com identificador do locatário (UsuarioId)
do / Permitir consulta, reedição de parâmetros e recálculo antes do fechamento com o cliente
exit / Bloquear alterações simultâneas durante envio para a fila de produção
Transições / IniciarImpressao() → EmImpressão | Excluir() [Confirmado via Modal (RN005)] → Removido
[ST03] EmImpressão (Active Production) RF015
entry / Ordem inserida na fila operacional de produção da oficina maker
do / Impressora 3D em execução física (consumindo filamento e energia elétrica)
exit / Exigir confirmação explícita do desfecho mecânico (Concluído ou Falha) (RN005)
Transições / Concluir() [RN005] → Concluído | RegistrarFalha() [RN005] → Falha
[ST04] Concluído (Terminal Operational) RN004 / RF017
entry / Deduzir automaticamente estoque físico: Material (g) e Insumos Químicos (mL) (RN004)
do / Totalizar receita e lucro líquido nos KPIs do Dashboard (RF029)
exit / Expurgo agendado ou transferência contábil de encerramento
Transições / Expurgo180Dias() → Histórico Financeiro | Excluir() [RN005] → Histórico Financeiro
[ST05] Falha de Impressão (Terminal Defect) RN004 / RF016
entry / Deduzir material consumido como perda física (RN004) e registrar sinistro mecânico ("espaguete")
do / Exibir alerta de perda no painel gerencial e permitir opção de reinício
exit / Limpeza de dados ou arquivamento contábil
Transições / ReiniciarImpressao() → EmImpressão | Expurgo180Dias() → Histórico Financeiro
[ST06] Cofre de Histórico Financeiro (Perpetual Archive) RN006 / RN007 / RF020
entry / Transferir consolidados contábeis (receita bruta, custo de insumos, energia e lucro) para HistoricoFinanceiro
do / Manter integridade histórica dos relatórios perpétuos sem degradar tabelas transacionais
exit / Imutabilidade perpétua (registro definitivo de inteligência contábil)

4. Máquina de Estados Complementar: Token de Recuperação de Senha

Ciclo de Vida do Token Criptográfico (RF034 / RNF006) Segurança OWASP ASVS
1. Token Inativo: Usuário em operação padrão, campo TokenRedefinicaoSenha = null.
2. Token Ativo e Válido: Ao acionar Esqueci Minha Senha, o sistema gera token de 256 bits de alta entropia com validade de 30 minutos (UtcNow + 30 min), grava no banco somente o hash SHA-256 do token e envia o link seguro via SMTP.
3. Senha Redefinida: Ao submeter nova senha forte dentro da janela de 30 minutos, o sistema aplica hash BCrypt (work factor 11), anula o token e limpa a data de expiração.
4. Token Expirado (Bloqueio Automático): Se UtcNow > TokenRedefinicaoExpiracao, o acesso pelo token é sumariamente rejeitado contra ataques de replay e força bruta.
